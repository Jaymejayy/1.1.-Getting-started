# Exercise 1.11 – Persisting Data

## Overview

This exercise demonstrates how to share persistent data between two Kubernetes applications: **Ping-Pong** and **Log Output**.

A PersistentVolume (PV) and PersistentVolumeClaim (PVC) are used to provide shared storage to both applications.

## Architecture

The two applications run in separate Kubernetes Pods but access the same persistent volume.

- **Ping-Pong:** Handles requests at `/pingpong` and saves the request counter in `pingpong.txt`.
- **Log Generator:** Generates a random UUID at startup and writes it together with a timestamp to `log.txt` every five seconds.
- **Log Reader:** Reads the contents of `log.txt` and the Ping-Pong counter from `pingpong.txt`, then displays both through an HTTP endpoint.

## Persistent Storage

The following Kubernetes resources were created:

- **PersistentVolume:** `example-pv`
- **PersistentVolumeClaim:** `shared-data-claim`
- **Storage capacity:** 1Gi
- **Access mode:** ReadWriteOnce
- **Storage class:** `my-example-pv`
- **Storage location:** `/tmp/kube` on `k3d-k3s-default-agent-0`

Both Deployments mount the same PVC at `/app/files`.

## Application Files

The shared volume contains:

- `log.txt` – Timestamp and random UUID generated by Log Output.
- `pingpong.txt` – Ping-Pong request counter.

## Kubernetes Manifests

Persistent storage manifests are located in:

```text
persistent-volumes/
├── persistentvolume.yaml
└── persistentvolumeclaim.yaml
```

The application Deployment manifests are located in:

```text
manifests/
```

## Accessing the Applications

**Ping-Pong endpoint:**

```text
http://localhost:8081/pingpong
```

**Log Output endpoint:**

```text
http://localhost:8081/
```

The Log Output endpoint displays the timestamp, random UUID, and current Ping-Pong request count.

Example:

```text
2026-11-24T13:00:00.000Z: random-uuid
2026-11-24T13:00:05.000Z: random-uuid

Ping / Pongs: 3
```

## Verification

The following commands were used to verify persistent storage:

```bash
kubectl get pv,pvc
kubectl get pods
kubectl rollout restart deployment/ping-pong-dep
kubectl rollout status deployment/ping-pong-dep
```

The Ping-Pong counter was verified to remain intact after restarting its Pod, confirming that the data was stored persistently.
